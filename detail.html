Designing a patent-pending, intuitive manipulator for the next generation of 3D tools

Autodesk - Project Falcon | 2026

Gizmos are visual aids in 3D software that allow users to manipulate objects. They commonly include move, rotate, and scale functions, which provide intuitive and precise control over object transformations. To learn more, watch this short tutorial video.

The Problem

The problem with existing gizmos in the majority of other 3D tools is that they are inaccessible on bright backgrounds, or when an object is a bright colour the colourful gizmo gets lost against it.

Additionally, they are complex tools designed to perform three transform actions (move, rotate, and scale) in a compact space so that users don’t have to move their cursor back and forth to the attribute editor, where they can manually adjust these transforms through input fields and sliders. Gizmos help get the job done in a small space. They are functional and intuitive for a more advanced user group already familiar with gizmos, but a new user—with little or no experience—can get lost without proper tutorials or guidance.

The Challenge

The challenge in designing gizmos is that we need to account not only for the ability to perform move, rotate, and scale transformations, but also to perform these actions along combinations of the positive and negative x, y, and z axes—and for the feedback mechanism that guides and helps new users understand the actions without unnecessarily confusing them with information that is irrelevant in the moment.

Discovery

Over the course of a week we explored just about every tool out there that had a gizmo. Our explorations didn’t stop at 3D tools—we also looked at games that use transform manipulators. We wanted to understand how games turn a boring 3D transform manipulator into a fun, interactive tool.

We then took a team vote on what we liked and disliked in each tool and came up with a list of features we wanted for our manipulator.

Exploration

My exploration included different types of contextual gizmo combinations:

  1. 3D coloured gizmo + bounding box: A 3D gizmo with different colours for three axes (x, y, z), and a bounding box that surrounds the selected object(s) and additionally acts as a manipulator for different actions.
  2. 2D gizmo without colour: A simple 2D (flat) gizmo that switches between move, rotate, and scale using a contextual toolbar underneath it.
  3. 3D gizmo without colour: A simple 3D gizmo with the same functionality as the 2D gizmo but in a more traditional three-dimensional shape, without colours for different axes.

After constant feedback and iteration loops with stakeholders, we landed on option 3 due to its simpler design that still resembles the traditional gizmo for more versatile usage. It would provide a simpler and cleaner user experience for new users while offering an on-ramp if they later preferred to learn more advanced 3D tools like Maya or 3ds Max. It would reduce the learning curve required to advance their 3D tool learning journey.

The Design

My hypothesis for the design of the manipulator was to make the elements in the gizmo appear contextually when needed, which would in turn keep the gizmo at any given point in time simple and reduce the overall complexity to only the actions necessary to achieve a certain transform.

After a lot of exploration and feedback sessions, we divided the gizmo into three contextual sections:

  1. Mini Gizmo: This is the default manipulator that performs move, rotate, and scale actions in a high-level, fast-paced way.
  2. Move & Rotate Gizmo: This manipulator performs move and rotate actions with precision.
  3. Scale Gizmo: This manipulator performs scale actions with precision.

But designing a manipulator that works regardless of the surface it’s placed on required a neutral colour for the body of the manipulator—but what happens when the background is the same as that neutral colour? The answer is that you wouldn’t be able to see it. For that reason, I added a silhouette in the other neutral colour (black) to create separation between the background and the body of the manipulator, which creates enough contrast between them.

I could have done it the other way around, where the body is black and the silhouette is white, but due to a flaw in our eyesight known as the chromatic dilation effect, that would make it look noisy on coloured backgrounds.

Mini Gizmo

The move interaction starts by hovering on the arrowhead. Based on whether a user moves it slowly or quickly, the supporting elements required to perform the move appear or disappear.

If a user is moving quickly, they are most likely trying to eyeball their 3D objects and won’t need precise snapping functionality, so it doesn’t appear in that case. However, if they decide to move slowly, they are most likely trying to move precisely and will get the precise snapping points tool.

Similar to moving, scaling follows the same set of rules, but the only difference is that moving the virtual point (blue dot) up upscales the object, and moving the point below the pivot point downscales the object.

For the rotate interaction, we also have precise-versus-fast capabilities. A user can free rotate by rotating the virtual point (blue dot) outside the ring, or precisely control rotation by snapping the virtual point to the dots inside the ring—which by default are set to 15-degree increments, though users can adjust the snapping increment from the properties panel if they choose.

Precision Gizmos

The move precision gizmo is activated either from the toolbar, which by default enables the precise gizmo, or by double-clicking the move arrowhead on the mini gizmo. Users can return to the mini gizmo by toggling it off in the toolbar or by deselecting and re-selecting the object.

Double-clicking the scale manipulator on the mini gizmo or from the toolbar—as with the move and rotate interactions described above—activates precision scaling mode, where a user can perform precise scaling from a context-focused manipulator.

Design Handoff

Handing off something meant to be used in 3D space needs to be designed in 3D. However, prototyping everything in Figma first made getting stakeholder feedback on the interactions and visual design easier and faster.

Next, once everything was finalized, I replicated the Figma designs in a 3D tool and handed them off in a .usd file to the developers to implement. They followed the Figma design files to read the interaction flows and the colour values for different interaction states.

Since the click targets are quite lean, it is good practice to add some buffer around the gizmo elements so it is easier to click the areas users intend to click, even when their cursor is not exactly on the shape. We call these hit boxes in 3D parlance—they provide room for error and less room for false positives and negatives.

The Impact

Our team ended up patenting this new gizmo before the launch.

After our launch in May of this year, we now have over 10k monthly active users using this tool and constantly providing feedback on Autodesk forums to help improve the tool.

We’ll continue improving the tool as we get more feedback, but so far we have positive user sentiment overall regarding the intuitiveness and usefulness of this new gizmo—a great morale booster and reassurance that we are meeting user expectations.
